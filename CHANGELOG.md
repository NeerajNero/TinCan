# Changelog

Newest first. Every behaviour change adds a line here in the same commit (see `docs/adding-a-feature.md` → Finish). Dates are commit dates.

## 2026-10-17

- **phase 18: rooms & fixes**. **Blank gaps instead of system lines**: `scripts/inspect-system-messages.mjs` (read-only) found every stored system line well formed (37 of the last 290 messages, all `type: "system"` with text). The cause was paint order: `ChatBackground` is an absolutely positioned layer and the message scroller wasn't positioned, so it painted over in-flow rows. Bubbles are `relative` and survived; system pills (and day separators) disappeared. The scroller is now `relative`. Also: every writer goes through `lib/chat/system.createSystemMessage(kind, text, meta?)` (server: `postSystemMessageAdmin(senderId, kind, …)`, shared `systemMessageData`), which signs as the current user (Pictionary/trivia results posted as the host used to fail the rules on the guest's phone). The hangout "Let's!" is now a `hangout` system line. `SystemPill` reads text, else derives a line from kind + meta, else ✨. System lines are excluded from the unread badge and divider, from read/delivered writes, and are written without `deliveredAt`/`readAt`; Home preview and toasts use `systemLine()`. Rules accept `kind` (≤32) and `meta` (≤8 keys) on system lines only. **Playlists**: `playlists/{watch|listen}` (≤50 items, unique, transactional edits over `lib/playlist.ts`), ★ by the current title with Undo, "Save to playlist?" chip, collapsible lazily loaded `PlaylistSection`/`PlaylistRows` (drag reorder, swipe/⋮ remove, now playing, who added); Listen rows play now, "+ Queue" and "Queue all" (`enqueueMany`, one multi-path write); `loadVideo` takes `playing`. **Room chat**: the Watch/Listen drawer is now its own thread at RTDB `roomchat/{room}` (`hooks/useRoomChat`, `lib/roomChat.ts`, `lib/db/roomChat.ts`) instead of the last 20 main-chat messages: 55dvh drawer that drags to 92dvh (`Sheet` `expandedHeight`), text-only composer, Copy / Share to main chat, Clear chat, unread dot via localStorage, no push or badge, trimmed to 50 by the sender. Composer Enter logic and auto-grow moved to `lib/composerKeys.ts` (now also ignores Enter during IME composition). `lib/localPref.ts` for guarded localStorage. New rules (messages kind/meta, playlists, roomchat) with emulator tests; unit tests for system lines, playlist helpers and room-chat trimming; knip now also treats `.tsx` tests as entries. Watch/Listen how-to sheets mention ★ playlists and the room chat. `/play/watch` initial JS 516.9 → 513.5 KB gzip, `/play/listen` 518.9 → 515.8.

## 2026-10-16

- **phase 17: pet life**: richer pet animation, stats logic unchanged. Sprites (`content/pets`) are now built from named SVG parts (breath › body, eyes › eyeL/eyeR, mouth, cheeks, accessory), each an `m.g` with its own controls. New `hooks/usePetLife.ts` (app wrapper around the injectable `usePetMotion`) and `components/pet/PetStage.tsx` drive it on `/pet` and in Home's widget (same motion, 88 px, no particles). Tap: 10 reactions under 700 ms, no immediate repeat; 3 taps in 2 s → 3 s excited sparkle burst; at most 20 particles alive. Long-press pets: wiggle + hearts, Joy tops up 20/s to at most 100, written once on release (`db/pet.pettedPet`, `lib/pet.sinceFor`). Feed is a ~2 s sequence (cookie, lean, three chomps with crumbs, write, wiggle + heart) and the bars now tween scaleX over 800 ms instead of width. Sleep/wake are ~1.5 s sequences that write `sleepAt` at the end; the card dims while asleep. Buttons are disabled during sequences, and a cut-short sequence still writes. Idle breathing, blinks, glances, fidgets and hungry/sad/happy idles pause while the tab is hidden. `db/pet` records its own writes so the friend's feed/play/sleep/wake replays here with a toast ("Sam fed Blob 🍪"); hug pings trigger a heart hop; level-ups spin with confetti, pop the accessory and count the badge up. Four chirps (`petTap`, `petFeed`, `petSleep`, `petWake`) under the Sounds toggle. Reduced motion: no loops/reactions/particles and actions write at once. Pure helpers in `lib/petLife.ts` with unit tests; new test-only `/e2e/pet` harness and `tests/e2e/pet.spec.ts`. Pet how-to mentions tap and hold.
- **phase 16e: YouTube playback**: root cause of the black Watch box, reproduced in Chromium. `YouTubePlayer` built `YT.Player` once, with the video id from its first render. On a phone that id is still null because `watch/main` arrives from RTDB after the lazy player mounts. `new YT.Player` then throws "Invalid video id", so no iframe is ever created and only the black container shows. The player is now built only once its node is mounted, the API is loaded and an id is known. Later ids are cued after `onReady`, and unmounting destroys it. `loadYouTubeApi()` loads `iframe_api` once, wraps an existing `onYouTubeIframeAPIReady`, reuses an existing tag and resets on failure. Second fix: the Permissions-Policy had `autoplay=(self)`, `encrypted-media=(self)` and similar, which denied those features to the YouTube iframe. It is now `buildPermissionsPolicy()` in `csp.ts` and delegates autoplay, encrypted-media, fullscreen and picture-in-picture to the two YouTube origins. Playback is gesture-safe. The new `hooks/useSyncedPlayer` Play/Pause calls the player inside the tap, then writes RTDB. Remote state applies only after a one-time "Tap to join" (`JoinOverlay`), and drift planning moved to `lib/playerSync.ts`. Watch gained a Play/Pause button. Listen keeps a 200 px player under an opaque cover card instead of a 1 px hidden one. `onError` codes go to Diagnostics as `[player]` lines, with friendly text over the player; 101/150 reads "This video can't be embedded". The CSP already allowed the embed, and a unit test now guards it, including no `'strict-dynamic'`. New test-only `/e2e/youtube` harness (404 unless `E2E_HARNESS=1`) and `tests/e2e/youtube.spec.ts` cover onReady with early and late ids, tap play/seek/pause, and Listen's player size.
- **phase 16d: Firestore probe**: phone diagnostics showed Firestore WebChannel transport errors on cellular followed by `img-src` blocking `https://www.google.com/images/cleardot.gif`, the probe Firestore loads to decide whether to fall back to long-polling. `csp.ts` now allows `https://www.google.com/images/` (path-limited, `FIRESTORE_PROBE_IMG`) in the page's img-src and in the worker policy's new img-src. Firestore is initialised with `experimentalAutoDetectLongPolling: true` explicitly (the SDK default, now documented). New `lib/firestoreHealth.ts` counts server → cache transitions of the `pair/main` listener (fed from `PairProvider`, no extra listener); More → Diagnostics shows "Firestore reconnects: went offline N times this session, last … ago, … offline in total". Unit tests cover the reducer and both policies; the Playwright CSP smoke test also loads the probe image.
- **phase 16c: how-to sheets**: `src/content/howto.ts` holds a title, a one-line label, 3–4 emoji-led steps and an optional tip for 21 games and together activities plus pet, plant, garden, jar, capsules, envelopes, daily question and the call-time finder. `SubHeader`'s new `help` prop adds a ? button that opens `HowToSheet` (on the shared Sheet). The sheet auto-opens on the first visit on a device, with seen keys kept in localStorage, and closes with "Got it". The pet, plant, garden and jar cards get a ? that never auto-opens. Play tiles take their sub-labels from the same content. More → "Show all tips again" clears the seen set. Tests cover the content shape and the open/remember/reset behaviour.
- **phase 16b: phone offline + diagnostics**: the permanent offline banner on Android came from the RTDB SDK's sticky long-polling. After one failed WebSocket it stores `firebase:previous_websocket_failure` in localStorage and starts every later session with long-polling, which loads `<script src="https://<db>/.lp…">` inside an iframe that `script-src` blocked, so it never connected. The database hosts are now in script-src and frame-src (unit-tested), and the flag is cleared before the first connection so each launch tries the WebSocket first. Lifecycle audit: nothing calls goOffline or disables the Firestore network, and presence on hidden only writes online:false. Updates: `UpdateWatcher` checks for a new worker on launch and resume, tells a waiting worker to skip, and offers "Update available, tap to reload" when a new worker takes control. More → Diagnostics (owner only, via `/api/gate`'s new `owner` flag) shows the build and worker build, auth token age, RTDB connected/transport/offset, Firestore online and last error, CSP mode, network, display and the last 20 errors, with Copy diagnostics.
- **phase 16: privacy & docs**: media is private. Uploads use `type=authenticated`; `POST /api/media/urls` signs a fixed variant set (`src/lib/media-variants.json`), stored as `variants` on messages, memories, journal, capsules and avatars, and only stored URLs render. The URL allowlist and the rules accept only public or signed delivery, and every variant is validated. Added `scripts/migrate-media-authenticated.mjs` (`pnpm migrate-media`, dry run by default), and the presets script now sets Signed + authenticated. GIPHY moved behind `GET /api/gif` (`GIPHY_API_KEY`, trending cached 10 min); `api.giphy.com` left the CSP. Access audit: no `dangerouslySetInnerHTML` (theme script is now `public/theme-init.js`), http(s)-only list links, the OSM credit opens safely, the YouTube player uses youtube-nocookie, live `/api/tick` responses carry counts only, and `/api/health` no longer echoes error messages. `pnpm export` backs up all Firestore data and media URLs. Polish: deleting a place unlinks its photos in one batch (new rule), save-to-memories is idempotent, and the offline banner's 4 s grace now applies to every disconnect. README rewritten.
- **phase 15d: CSP fix + recent games**: the CSP is now built in `csp.ts` and set per request by `src/proxy.ts` with a nonce, so script-src has no `'unsafe-inline'` and every page renders dynamically. The service worker gets its own policy, and Serwist's cross-origin catch-alls are removed, so the worker no longer fetches avatars, YouTube scripts or radio streams. Every cached host is now in connect-src too; the old policy lacked them, which blocked `lh3.googleusercontent.com` from the worker. Added `pnpm test:e2e` CSP checks covering both page and worker. Recent games crashed on trivia and Pictionary rows because `GAME_META` only knew board games and results were written as `game as GameType`. There is now one catalogue (`lib/games/catalog.ts`, safe `gameInfo()` fallback) used by Recent games, the record strip (now including trivia and Pictionary), Home's game card, invites and result messages. Pictionary results no longer say "won the trivia duel". Recent games sits in a widget `ErrorBoundary`. New unit tests cover every result type.
