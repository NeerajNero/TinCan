## Smoke tests (`pnpm test:e2e`)

`tests/e2e/youtube.spec.ts` opens the test-only `/e2e/youtube` harness (served only with `E2E_HARNESS=1`, which `playwright.config.ts` sets) with YouTube's sample video `M7lc1UVf-VE`. It asserts that `onReady` fires and the video is cued when the id arrives at mount and 1.5 s later, the way the RTDB value does. It also checks that Play, Seek and Pause taps change the player state, and that Listen's covered player is at least 200×200 and plays. It needs network access to YouTube.

`tests/e2e/pet.spec.ts` opens the test-only `/e2e/pet` harness (`components/dev/PetHarness.tsx`, same `E2E_HARNESS=1` gate): the real `PetStage` and `usePetMotion` with a local pet doc, buttons that simulate the friend, and every write/toast logged to `window.__pet`. It checks that Feed disables the buttons and writes after the chomps (1–1.9 s), that Tuck in / Wake write only after ~1.4 s, that 24 rapid taps never show more than 20 particles, that a long-press writes once on release with a higher value, that the friend's feed replays with a toast and no write, the level badge, the Home size (no particles) and reduced motion (immediate write, no particles).

`tests/e2e/keyboard.spec.ts` opens the test-only `/e2e/keyboard` harness (`components/dev/KeyboardHarness.tsx`, same gate): the shared `components/games/LetterKeyboard` in both shapes (Hangman's letters-only with used keys, the daily word's with Enter / Backspace) inside the app column and card padding. At 360 px and 320 px it asserts each keyboard's `scrollWidth` equals its `clientWidth`, every key lies inside the viewport with a positive width, the document has no horizontal overflow, a used Hangman key is disabled and a tap disables a fresh one, and no errors were collected.

`tests/e2e/boards.spec.ts` opens the test-only `/e2e/boards` harness (`components/dev/BoardsHarness.tsx`, same gate): tic-tac-toe, Connect Four, checkers, chess, Dots and Boxes, both Battleship grids, pixel art and the drawing canvas with mid-game positions, inside the app column. At 320, 360 and 411 px it asserts, per board, that no two `[data-cell]` bounding boxes intersect (0.5 px tolerance; adjacent cells may touch), no cell leaves the viewport, the board's `scrollWidth` equals its `clientWidth`, every `[data-grid]` is square within 1.5 px, and that the page has no horizontal overflow and no errors. Soft assertions, so one run lists every failing board.

The same spec covers the GameScreen composite through `/e2e/game-screen?screen=word|hangman` (`components/dev/GameScreenHarness.tsx`: the composite inside a stand-in app shell with a tab-bar-sized last row): at 320 / 360 / 411 px × 740 / 826 px it asserts the dock has content and its bottom edge is inside the viewport and above the tab bar, the document and `<main>` do not scroll, the content area fits without scrolling, the keyboard's `scrollWidth` equals its `clientWidth`, the word grid keeps 5:6, and no horizontal overflow or errors. Unit tests: `tests/unit/haptics.test.ts` (patterns, no-op without the API), `tests/unit/gameScreen.test.tsx` (header / content / dock placement, `<Dock>` from inside the content lands in the dock; `Pressable` buzzes 10 ms on press and nothing when disabled).

`tests/e2e/violations.ts` is the shared error collector for the harness specs (`collectErrors(page, counts?)`: page errors plus console errors, CSP and Permissions-Policy violations included; the spec asserts the list is empty). It ignores exactly two third-party messages and logs each as `[e2e] ignored third-party noise (…)`: the CSP refusal of Google sign-in's `https://apis.google.com/js/gen_204` beacon, and `Permissions policy violation: compute-pressure …` when its source is a `www.youtube.com` / `www.youtube-nocookie.com` document. The CSP and Permissions-Policy themselves are unchanged. `tests/e2e/violations.spec.ts` proves both are really raised and ignored (a stubbed youtube-nocookie frame calls the Compute Pressure API; the page fetches gen_204) and that look-alikes (another apis.google.com path, compute-pressure from our origin or a spoofed host, another feature from YouTube) still count. `tests/e2e/csp.spec.ts` collects raw `securitypolicyviolation` events instead of console lines, so it applies the same single exception through `cspNoiseReason` (`connect-src` + that exact gen_204 path, logged the same way; checked in `violations.spec.ts`). Add any future exception there, with its own self-check.

`tests/e2e/csp.spec.ts` checks that `/signin` is served with an enforced, nonce-based CSP with no `'unsafe-inline'` in script-src. It then waits for the service worker to control the page, requests an image from every host the worker caches plus Firestore's probe image (`www.google.com/images/cleardot.gif`), and fails on any `securitypolicyviolation` in the page or inside the worker. A self-check proves both listeners fire on a deliberate violation.

`tests/e2e/layout.spec.ts`: Playwright on a Pixel 7 viewport against a production build (`next build` then `next start -p 3100`; no sign-in needed). For `/signin` and `/offline` it asserts `document.documentElement.scrollHeight` equals the viewport height, both as shipped and with the html/body clamp lifted (the clamp alone would only clip a too-tall screen), at full height and at a 200 px-tall viewport, and that `window.scrollTo` can't move the page. First run needs `npx playwright install chromium`. There is no CI pipeline in the repo yet; run it before pushing layout changes.

## Turn latency (`pnpm perf:turn`)

`scripts/perf-turn.mjs` runs inside `firebase emulators:exec --only auth,firestore,database --project demo-tincan`: it generates a throwaway service account, builds the app with emulator settings (`--skip-build` reuses `.next`), starts `next start -p 3123`, creates two verified users on the allowlist and takes their ID tokens from the Auth emulator, seeds a Battleship game in the firing phase (both fleets in `gamePrivate`), a Hangman round and a tic-tac-toe node, then for each of 12 runs (first 2 discarded) reseeds and times the request to (a) the HTTP response and (b) an RTDB listener seeing `moves` grow, which is what a phone's board waits for. `--out file.json` keeps the numbers. Everything is on localhost, so the absolute figures are small; compare runs and count awaited round trips. Reference (perf: turn latency): shot 31 → 12 ms response, 22 → 11 ms to the listener; guess 23 → 10 / 19 → 9; a local transaction 4 / 2 unchanged.

## Profiling the chat list (`pnpm profile:chat`)

`tests/perf/chat.profile.test.tsx` mounts `MessageList` with 300 messages under React's `<Profiler>` in happy-dom and appends ten more, printing the mount cost and the median append commit. It asserts an append costs under a quarter of the mount (the memoised bubbles must not re-render). Numbers are an upper bound: happy-dom is slower than a phone's Chrome. Windowing (`@tanstack/react-virtual`) is only worth adding if an append exceeds ~16 ms in a real browser.

## Automated: security rules

`tests/rules.test.ts` runs against the Firebase emulators with `@firebase/rules-unit-testing` and vitest. It reads `ALLOWED_EMAILS` and `NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME` from `.env.local` / `.env` so the generated rules match.

```bash
brew install --cask temurin   # Java, once (the emulators need it)
pnpm test:rules               # = rules:build + emulators:exec + vitest
```

The emulators write `firestore-debug.log` and `database-debug.log` into the repo root; they are gitignored.

Covers: allowlist deny, message create/update constraints and Cloudinary URL prefix, invite system lines (required meta, extra keys, off-site routes), capsule and envelope private bodies, gifts-list privacy, `pair.uids` immutability, RTDB pings and invites ownership and shape, presence validation, playlists, room chat, and every write the live trivia node takes (own join, start rewrite, own answer, advance, remove). Add a case for every rule you touch (allow + deny).

`tests/trivia-live.test.ts` runs in the same `pnpm test:rules` pass: two authenticated emulator clients drive `lib/db/trivia` exactly as the screen does (`createRound` → `openLiveSession` on both → `answerLive` → racing `advanceLive` → `switchToAsync`) and assert both reach question one, the round waits for the second player and starts once, answers advance in lockstep, and switching to async ends the session on the other phone. Against the pre-phase-21 rules the first case fails with both clients in `error: PERMISSION_DENIED`, which is the stall it reproduces.

## Static

`pnpm typecheck` (Next typegen + tsc) and `pnpm lint` (Next + TypeScript + React Compiler rules). Both must pass before a commit. `pnpm build` catches worker/config regressions and prints the route bundle sizes.
