# Security

## Model

Two allowlisted Google accounts are the only principals. Everything else is denied at three layers: the Firestore/RTDB rules (the real boundary), the API guard (server routes), and the client gate (UX only).

## Allowlist

`ALLOWED_EMAILS` (two emails) is read by the server (`lib/allowlist.ts`) and baked into the rules by `scripts/build-rules.mjs` from `rules/*.tmpl` (`__ALLOWED_EMAILS__`, `__CLOUDINARY_CLOUD__` placeholders). The generated `firestore.rules`, `database.rules.json` and `.firebaserc` are gitignored, so emails never land in git. Changing the allowlist = update env in all places + `pnpm rules:deploy` + redeploy Vercel.

## Rules (`rules/firestore.rules.tmpl`, `rules/database.rules.json.tmpl`)

Default deny. `allowed()` requires a signed-in, `email_verified`, allowlisted user. Then per collection (full table in data-model.md):

- **Ownership**: `users/{uid}` own-write; `email`/`createdAt` immutable; no unknown top-level fields. `moods`, `wordle` own-write (`availability` went with the Call-time finder in phase 29).
- **Messages**: create only as sender with `createdAt == request.time`, text ≤2000, type enum, media URLs must be `https://res.cloudinary.com/<cloud>/` (gif: `https://media*.giphy.com/`). Recipient may only touch `deliveredAt/readAt/status`; sender edits/deletes; either sets only its own `reactions.{uid}` / `deletedFor` entry.
- **System lines**: `kind` (string ≤32) and `meta` (map ≤8 keys) are accepted only when `type == "system"`; other types may not carry them. `kind == "invite"` additionally requires `meta` to hold exactly `route` (a same-origin path `^/…`, never `//host`, ≤ 100), `activity` (≤ 32), `label` (1–80), `expiresAt` (number) and optionally `roundId` (≤ 64), so a card can only ever send Join inside the app.
- **Playlists**: `playlists/{watch|listen}` only; keys limited to `items`, `updatedAt` (server time), `updatedBy` (must be the writer); `items.size() <= 50`.
- **Private bodies**: `capsules/{id}/private/body` readable by author or when `request.time >= unlockAt`; `envelopes/{id}/private/body` readable by author, or by `forUid` once `openedAt` is set.
- **Snaps** (phase 27): `snaps/{dateKey}` is read by both; each poster may merge only its own uid key into `posted` / `thumbs` (our Cloudinary URL) / `late`, with `dateKey == id` and no other keys. `snaps/{dateKey}/entries/{uid}` is created only by `uid` (entry shape, `at == request.time`, `savedToMemories: false`) and read by the other person **only if `exists(/snaps/{dateKey}/entries/{request.auth.uid})`** — "post yours to see theirs" is the rule, not the UI; the owner may change caption / savedToMemories within 10 minutes of `at` (`duration.value(10, 'm')`), either person may set `savedToMemories` to true any time, nobody deletes (the tick does, with admin). The summary's thumbnail is readable before posting; the client doesn't render it until the person has posted.
- **View-once**: `messages.viewOnce` is a bool allowed only on image / voice lines and only on create (with `viewedAt` empty); `viewedAt` is written by the recipient, once, as server time, alongside the receipt fields. `DELETE /api/media` (admin) lets the recipient of a view-once line destroy the asset and clear `media`.
- **users**: `homeCards` is a map of `order` / `hidden` lists (≤ 24 each); `note` is null or `{ text 1–60, emoji ≤ 8, at (timestamp), expiresAt (timestamp) }`; both owner-only like every other field. `inbox` (phase 28) is a map of `unread` (int ≥ 0) and `lastReadAt` (timestamp | null) — `inboxOk()` — and `inboxOnlyRead()` adds, on update: when `inbox` is among the changed keys, `unread` must be 0 and `lastReadAt` a timestamp. The server bumps the count with the admin SDK; a bumped value already on my doc never blocks my other edits (only the diff is checked).
- **Inbox rows**: `inbox/{uid}/items/{id}` — read and delete by `uid` only, no client create or update, nothing at `inbox/{uid}` itself; the friend and strangers see nothing.
- **Lists** accept only the `bucket` and `wishlist` kinds (phase 29 removed gifts and todo; `scripts/cleanup-plan.mjs` deletes leftovers).
- **Events** (phase 29): read by both; create only as `createdBy == uid` with `createdAt == request.time`; update by either with `createdBy` / `createdAt` unchanged; delete by either; `eventShape()`: the ten known keys only, title 1–60, emoji ≤ 8 or null, `date` / `endDate` yyyy-MM-dd with `endDate ≥ date`, `time` HH:mm, `who` 1–128, note ≤ 200, countdown bool. On `pair/main`, `nextCountdownOk()` (map of id / title ≤ 60 / emoji / date / endDate / who, or null) and `eventAddedOk()` (at number, by, title ≤ 60, date, emoji).
- **pair/main**: `uids` can only grow and never lose a uid; `chatBg` is a built-in id or one of our Cloudinary photos; `play` holds only `recent` (list ≤ 8) and `favourites` (list ≤ 6); `snap` keeps `todayKey` / `todayAt` as the tick wrote them (a client may only write `streak`).
- **Admin only**: `push`, `tickLog`, `quota`, `scheduled` delivery fields. RTDB `meta/rulesVersion` is readable by the pair and written only through the Firebase CLI's admin access (`pnpm rules:stamp`); its `.validate` pins the `RULES_VERSION` the live rules were built from.
- **RULES_VERSION**: `scripts/build-rules.mjs` embeds a hash of the two templates (`scripts/lib/rules-version.mjs`) in both rules files; `next.config.ts` bakes the same hash into the app (`NEXT_PUBLIC_RULES_VERSION`). The daily tick job compares the live markers (admin `getRules()`, Firebase Rules API) with the build's and pushes the owner on a mismatch; More → Diagnostics shows the same line. The rules now deploy from CI (`deploy-rules`, operations.md), so the live rules can no longer silently lag the templates.
- **RTDB**: `presence/typing/cursors` own-write with validated shapes (presence page ≤100 chars, cursor coords 0–1); `pings/{uid}/{id}` created by the other user, deleted by owner; `invites/{uid}/{id}` the same, plus owner-only read and a validated shape (`from == auth.uid`, activity ≤ 32, label 1–80, same-origin `route`, `at ≤ now`, no other children); `trivia/{id}` (live duel) validates `qIndex`/`qStartedAt` numbers, `startedBy` string, and `joined/{uid}` / `answered/{uid}` as numbers that are the caller's own key or unchanged (the start/advance transactions rewrite the node), nothing else; `games` validate `type/state/turn/status/open/endReason/players`; `gameReactions/{gameId}/{id}` create only as yourself with `by`, `emoji` (1–8 chars) and `at` (number) and nothing else, delete by either, never edited; `whiteboard`/`pictionary` strokes ≤24k chars; `pixel/grid` exactly 1024 chars. `roomchat/{watch|listen}/{id}`: create only when empty with `uid == auth.uid`, delete by either (trim, clear), no edits; text 1–500 chars, `at` ≤ now, no other children; unknown rooms denied. `gamePrivate/{gameId}/{uid}` (Hangman words, Battleship fleets) is readable and writable by `$uid` only, with `word` (lower-case letters and spaces, 1–20), `round` (number) and `fleet` (string ≤ 600) the only children; it is its own top-level node because RTDB read permission cascades, so anything under the both-readable `games` would be visible to the other player. The moves that need the hidden value (a Hangman letter, a Battleship shot) go through `POST /api/games/*`, where the admin SDK reads it and rewrites the shared node in a transaction after checking whose turn it is.

Covered by `tests/rules.test.ts` (emulator; phase 23 added the three new `games.type` values and `gamePrivate/{id}/{uid}`: owner-only read and write, the word / round / fleet shape, no other children; phase 27 added the snaps summary and entries — the friend's entry refused before I post and allowed after, own-key merges, the 10-minute caption window, save-to-memories by either —, `homeCards` / `note` shapes on users, `pair.snap` (streak only), and `viewedAt` only by the recipient, only on a view-once line, once) and, for the live trivia handshake end to end, `tests/trivia-live.test.ts`. Run `pnpm test:rules` after any rules change; phase 28 added the inbox rows (owner reads / deletes, nobody creates / edits, the friend sees nothing) and the `users.inbox` write (zero + server-time stamp only; a server-bumped count never blocks other edits); phase 29 replaced the gifts test with the two remaining list kinds (gifts / todo refused) and added events (create as yourself with server time, edit / delete by either, `createdBy` immutable, every shape bound) and the `pair.nextCountdown` / `pair.eventAdded` mirrors.

A rule that silently denies a path is now visible: both SDK wrappers (`lib/firebase/fs.ts`, `lib/firebase/rt.ts`) log every rejected write and every denied read or listener to More → Diagnostics, and development shows a toast. Phase 21's live trivia stall was exactly this: the RTDB template had no `trivia` node, so the cursor listener was denied and, with no cancel callback, never fired.

## API guard (`src/lib/server/guard.ts`)

Route keys: `push`, `media`, `sign`, `urls`, `gate`, `gif`, `games` (the two game-move routes: bucket 40 / 1 per s) and `rules` (`GET /api/rules/status`: bucket 5 / 0.05 per s, 50 a day; it calls the Rules API with the service account's token). The game routes use `guardFast` (perf: turn latency): the ID token is verified locally against Google's cached public keys without the revocation lookup, the token bucket is in memory only and nothing touches Firestore (no daily cap). Accepted trade-off: a revoked session can keep moving pieces in games it is already in until its token expires (≤ 1 h), but it cannot send, upload or spend anything, which stays behind the full `guard`.

ID token verified with revocation check → `email_verified` + allowlist → per-uid token bucket → Firestore daily cap (`quota/{uid}_{day}`: push 1000, media 300, sign 300) → 16 KB body → `.strict()` zod. `/api/tick` compares `x-tick-secret` with `timingSafeEqual`. Response bodies carry only an error code.

## Media

Uploads are **signed** and **private**. The browser asks `POST /api/media/sign` for a signature over a fixed parameter set (timestamp, folder, preset, `type=authenticated`, the incoming transformation for images), after a size check (5 MB / 3 MB). It uploads straight to Cloudinary, then calls `POST /api/media/urls` once for signed delivery URLs of the fixed variant set, and stores them on the doc. Authenticated assets return **401** without a valid signature, and a tampered transformation also gets 401 (verified against the live cloud). A signed URL never expires and opens exactly one variant of one asset; anyone holding it can load that variant, so treat the URLs (and `pnpm export` output) as private.

The presets `tincan_image` and `tincan_audio` must be Signed mode with delivery type authenticated (`pnpm cloudinary:presets` sets both). Deletes go through `DELETE /api/media`, which checks the caller owns the doc and destroys the asset under either delivery type. The app renders only `res.cloudinary.com/<cloud>/(image|video)/(upload|authenticated/s--sig--)/…` and GIPHY media (`lib/safeUrl.ts`); the rules enforce the same pattern on every stored URL and variant. User-typed links (lists) render only when http(s).

## Headers (`next.config.ts`)

- `Content-Security-Policy` is **enforced** and built in `csp.ts`. `src/proxy.ts` generates a nonce per page request; `script-src` is `'self' 'nonce-…'` plus YouTube, `s.ytimg.com`, `apis.google.com` and the Realtime Database hosts, with no `'unsafe-inline'`. The database hosts are there because its long-polling fallback loads scripts and a disconnect iframe from them; `frame-src` lists them too. Next stamps the nonce on its inline bootstrap scripts and the root layout on the theme script. `img-src` includes `https://www.google.com/images/` (path-limited, `FIRESTORE_PROBE_IMG`): Firestore's WebChannel transport loads `cleardot.gif` from there as its connectivity probe before falling back to long-polling, and blocking it kept phones on cellular offline. Hashes and SRI were tried and don't work: SRI only covers external files, and Next's inline scripts differ per route and per build. The cost is that every page is dynamically rendered.
- The service worker has its own policy, from the `/serwist/*` response headers: `default-src 'self'; script-src 'self'; img-src 'self' https://www.google.com/images/; connect-src <same list>`. Its runtime-cache fetches count as connect-src, so every cached host (Cloudinary, OSM tiles, GIPHY, ytimg) is in connect-src as well as img-src. Serwist's two cross-origin catch-all routes are removed, so avatars and YouTube scripts no longer pass through the worker, and a fetch listener registered before Serwist's stops every radio host (`RADIO_HOSTNAMES`, from `lib/radio.ts`) without `respondWith()`, so streams are never intercepted or cached.
- Radio: `media-src` lists every stream origin plus each station's redirect/segment `hosts` (`RADIO_MEDIA_ORIGINS`); `connect-src` lists only the HLS ones (`RADIO_HLS_ORIGINS`), which hls.js fetches on browsers without native HLS. Exact hosts, never `*.cloudfront.net`. The mp3 hosts left connect-src: only `<audio>` loads them.
- If something breaks, set `CSP_REPORT_ONLY=1` on Vercel to send both policies as report-only, fix `csp.ts`, then unset it. `script-src` must never gain `'strict-dynamic'`: browsers would then ignore the host entries and the YouTube IFrame API (`www.youtube.com/iframe_api`, which loads `www-widgetapi.js` from the same host) would stop loading. A unit test guards this along with the YouTube frame-src and ytimg img-src entries. `pnpm test:e2e` checks that the header is enforced and nonce-based, and that loading `/signin`, every cached image host and the Firestore probe image raises no violation in the page or the worker.
- `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` from `buildPermissionsPolicy()` in `csp.ts`: microphone for us only, and autoplay, encrypted-media, fullscreen and picture-in-picture for us plus the two YouTube origins (`YOUTUBE_ORIGINS`). Without that delegation the browser denied the YouTube iframe autoplay even though it asks for it, so synced play counted as blocked autoplay. Everything else is `()`. Unit-tested. `/serwist/*` is `max-age=0, must-revalidate`.

## Third parties

The full list of what leaves Firebase and Cloudinary, and to whom, is in the README under Privacy & access. GIPHY is called only from `/api/gif` (key server-side). The YouTube player uses `youtube-nocookie.com`. `/e2e/youtube` is a test-only harness page: it 404s unless the server runs with `E2E_HARNESS=1`, which only Playwright's web server sets. `/api/tick` live responses carry counts only. `/api/health` reports booleans and an error name.

## Secrets handling

- All env values live in `.env` / `.env.local` (gitignored) and on Vercel. Scripts read `.env.local` then `.env` and **never print values**; emails are masked in output.
- `FIREBASE_SERVICE_ACCOUNT` is base64 JSON consumed only by `lib/firebase/admin.ts` (and, as a GitHub Actions secret, by the `deploy-rules` job through `GOOGLE_APPLICATION_CREDENTIALS`); `CLOUDINARY_API_SECRET` only by `/api/media` and `/api/media/sign`; `TICK_SECRET` only by `/api/tick`.
- The service worker caches only images and tiles (CacheFirst) and never Firebase, Google or `/api/*` responses.
- `NEXT_PUBLIC_*` are public by design (Firebase web config, Cloudinary cloud name). `GIPHY_API_KEY` is server-only. The client bundle was grepped for every secret name and value (Cloudinary secret, tick secret, GIPHY key, service account and its private key): 0 matches.
- `/api/health` returns booleans only.
- Dependency overrides in `package.json`: `jose@5.10.0` (firebase-admin ESM crash on Vercel) and `@grpc/grpc-js >= 1.13.6` (advisory). Run `pnpm audit --prod` after upgrades.
