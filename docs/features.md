# Features → code

Pages under `src/app/(app)/**` are thin: they render one screen component. Logic lives in `src/lib/db/*` (Firestore/RTDB access), `src/lib/*` (pure helpers) and `src/hooks/*`.

## Home (`/`) — `components/home/HomeScreen.tsx`, data from `hooks/useHomeData.ts`

**Snap takeover and digest** (phase 27b). `Cards` also decides two things before the list: `lib/snap.snapTakeoverDue` (today's minute has come, my entry is missing, this device hasn't dismissed today → `components/snap/SnapTakeover`, a full-screen Portal with a two-minute countdown from its appearance over the shared `SnapCapture`; "Not now" writes `tincan:snap-dismissed` = dateKey) and `lib/homeDigest.homeDigestInput` (what happened since `users/{me}.lastOpenAt`, captured once per mount, from data Home already holds) → `DigestCard`, which renders `lib/digest.digestItems` as chips and writes `lastOpenAt` (`lib/db/users.touchLastOpen`) on dismiss, on a chip tap, or after 30 s.

**Layout** (phase 27). `HomeScreen` renders the cards from a map keyed by `HomeCardId` in the order `lib/homeCards.homeCardOrder(me.homeCards, pins)` returns: the saved `users/{me}.homeCards = { order, hidden }` normalised (unknown ids dropped, missing ids appended in default order), minus hidden cards, with pinned cards first — `snap` while `snapPinned(state)` (the window is open or today's snap is unposted), then `games` while `isMyMove` is true for any open game; a pinned card shows even when hidden. The milestone banner and the sleep/wake toggle sit outside the order. More → `HomeLayoutCard` edits the preference (`Reorder` rows with a drag handle, a Switch per card, Reset to default → `deleteField`). `useHomeData` is called once in `HomeScreen` and passed down, so the card order never doubles listeners.

## Chat (`/chat`) — `components/chat/ChatScreen.tsx`

- `hooks/useMessages.ts`: latest 50 live, `load older` pages of 50 (auto up to 3 pages by scroll, then a button; oldest pages dropped when back at bottom), optimistic sends, delivered/read marking.
- `MessageList` (day separators, unread divider, jump-to-latest FAB), `MessageBubble` (swipe-right reply, long-press menu, reactions), `MessageMenu` (react/reply/copy/edit ≤15 min/delete for me/everyone/schedule), `Composer` (text, attachments, hold-to-record voice with slide-to-cancel, GIF/sticker panel), `ScheduleSheet` (scheduled messages), `Ticks`.
- **View-once** (phase 27): the `Composer` shows the 👁️ `ViewOnceToggle` (`chat/media/ViewOnceToggle`) only inside an attachment preview: at the end of `AttachmentStrip` after picking photos (Memories' `PhotoPicker` uses the strip without it), and in the recorded voice note's preview row — releasing the mic now sets `clip` (duration, 👁️, discard, "Send voice note") instead of sending at once; off by default, icon-only in both states (filled with the accent when on; "View once" is the tooltip / accessible name), reset after every send or when the preview goes away (`tests/unit/composer-view-once.test.tsx`); `useUploads.sendImages / sendVoice` take the flag, append `?once=1` to the stored URL and variants (`lib/viewOnce.onceUrl / onceVariants`; the worker's `isOnceRequest` route is `NetworkOnly`) and `sendMedia(…, viewOnce)` writes `viewOnce: true, viewedAt: null`. `MessageBubble` renders `ViewOnceBody` from `lib/viewOnce.viewOnceState`: the recipient gets "👁️ Photo · tap to view once" (`onOpenViewOnce`), the sender "👁️ View once · not opened yet", both "👁️ Opened" (sender with the time) once `viewedAt` is set or `media` is gone. `ChatScreen` opens the plain `ImageViewer` with no actions, or `media/ViewOnceVoice` (a Sheet that plays once, no scrub); closing either calls `markViewed` then `deleteViaServer("message", id)` — `DELETE /api/media` lets the recipient of a view-once message destroy the asset and clear `media` without marking the line deleted; a failed call lands in localStorage `tincan:viewonce-pending` and `LiveEventsProvider` retries it on the next app open (dropping `not_found` / `forbidden`). `mediaLabel` says "👁️ Photo" / "👁️ Voice note" in previews and pushes.
- Media: `media/*` (AttachmentStrip, UploadBubble + ProgressRing, ImageViewer with pinch-zoom, VoicePlayer 1×/1.5×, MediaPanel for GIF/stickers). Upload pipeline in `hooks/useUploads.ts` → `lib/media/compress.ts` (≤1080 px, ~0.3 MB) / `lib/media/recorder.ts` (opus 32 kbps, ≤2 min) → `POST /api/media/sign` → Cloudinary (authenticated) → `POST /api/media/urls` → signed `variants` stored on the message. Rendering goes through `lib/mediaUrl.ts` (`variantUrl`) and `ui/CloudImage`. GIFs come from `GET /api/gif` (`lib/giphy.ts`).
- Typing: `hooks/useTyping.ts` (RTDB `typing/{uid}`, 1.5 s throttle, 3 s expiry). Unread badge: `hooks/useChatMeta.tsx`.
- Rendered URLs are filtered by `lib/safeUrl.ts`; links auto-linked by `lib/linkify.tsx`.
- **Backgrounds**: `ChatBackground` is one absolute layer behind the scroller (`backdrop` prop of `MessageList`); `ChatBackgroundPicker` (palette button in `ChatHeader`, and More → Chat wallpaper; "Shared with <friend>") writes `pair/main.chatBg` + `chatBgBy` (`lib/db/pair.setPairChatBg`) so both see the same wallpaper. `LiveEventsProvider` runs the one-time migration off the legacy `users/{me}.chatBg` (`lib/wallpaper.planWallpaperMigration`: copy to the pair when it has none, then `deleteField`) and toasts "<friend> changed the wallpaper 🎨" when `chatBg` changes with `chatBgBy` = the friend (no chat line, no push). Built-ins live in `content/chat-backgrounds.ts`; the photo option reads one bounded page of `memories`.
- **System lines**: every writer goes through `lib/chat/system.createSystemMessage(kind, text, meta?)` (server: `postSystemMessageAdmin(senderId, kind, text, meta?)`), sharing `systemMessageData` in `lib/chat/systemKinds.ts`: `{ type: "system", kind, text, meta?, senderId, status: "sent", createdAt }`. Kinds: sleep, wake, relationship, game-result, game-cancel, twenty-result, pet-adopt, pet-fed, pet-level, pet-hungry, garden-sticker, capsule-unlock, hangout (legacy: the removed hangout wheel wrote it; kept so old lines render), invite (rendered by `InvitePill`, see Invites under Play), recap (the monthly numbers line the tick posts on the 1st; `lib/recap.recapLine`), envelope-open (phase 27b: written by `EnvelopesScreen` when the recipient opens one, so the author sees it in the app, not only as a push). `SystemPill` shows the text, else a line derived from kind + meta, else ✨, so a row is never empty; old lines render unchanged. System lines never count as unread (badge, divider), never get read/delivered writes and never show ticks; the Home preview and toasts use the same `systemLine()`. The scroller is `relative` so the absolute background layer can't paint over in-flow rows (the phase 18 blank-gap bug).
- **Rendering cost**: `MessageBubble` is `React.memo` with stable callbacks; presence lives in `PresenceProvider` and typing in `useFriendTyping` inside the header, so the list never re-renders for them. `pnpm profile:chat` measures it.

## Play (`/play`) — `components/play/PlayScreen.tsx`

**Landing** (chore: play tab layout). `lib/play/catalog.ts` is the one list of everything Play opens (`PLAY_ENTRIES`: the seven board games, eight quick-play screens, eight together activities; id = how-to key, `short` label, `href`, `section`), with `playInfo()` for ids from storage, `playIdForPath` / `gameIdForPath` for routes and `pickSurprise`. Top to bottom: the "🎲 Surprise us" chip (random entry → the lobby flow for a board game, `router.push` otherwise, plus a toast naming it); "Jump back in" (invites for me, then active games ranked my turn → their turn → invite sent); "Recent" (`pair.play.recent`, first 4 known ids) and "Favourites" (`pair.play.favourites`), both hidden when empty; then Board games / Quick play / Together, each a `TileRow` of `CompactTile`s (3.5 visible, snap, the page gutter used for bleed) or, after "See all", the two-column `BigTile` grid. The per-section choice is `localStorage` `tincan:play-open:{section}` (`lib/play/usage.sectionOpen`: remembered value wins, else collapsed once Recent has entries). `badgeFor(entry)` gives every tile the same status (`TileBadge`: full text for big tiles, a short pill for compact ones): board games from the open-games list (Inviting… / Invite sent / Invited you! / Your turn / Their turn), the daily word from today's two wordle docs, Know-me from untaken quizzes, and "<friend> is here" from presence for any screen of its own. Long-press (touch) or right-click (mouse) on any tile opens a `Sheet` with Open and Pin to favourites / Unpin (`PlayTile.usePressMenu`: 450 ms, a 10 px move or a scroll cancels, the click that ends a long-press is swallowed). The dots size sheet, "Just finished" and the Record strip are unchanged.

**Usage** (`lib/play/usage.ts`, pure; `lib/db/play.ts` writes): `recordRecent(usage, id, by, now)` prepends `{ id, at: client ms, by }`, de-duplicates, caps at 8 and returns null when the same id was recorded less than 10 minutes ago (whoever opened it); `toggleFavourite` caps at 6 (null = full → "Favourites are full" toast). `components/play/PlayUsageTracker` (mounted once in `AuthGate`, no listener of its own) watches the pathname: a screen of its own resolves through `playIdForPath`, a board game (`/play/{id}`) through the open-games list from `LiveEventsProvider`, then `trackPlayOpen` writes `play.recent` (a per-device map stops two quick opens racing the snapshot into two writes). Both writes are dot-path `updateDoc`s on `pair/main`; the rules check the list sizes.

**Game catalogue** (`lib/games/catalog.ts`): names, emoji, routes and result wording for every game that writes `gameResults` (the seven board games, trivia, pictionary, the daily word), with `gameInfo()` falling back to a neutral entry for unknown types. Used by Recent games (`RecentGamesList`, inside an `ErrorBoundary`), the record strip (ten games, five per row), Home's game card, invites, result toasts and the system messages.

**Game layout** (phase 26). `components/play/GameScreen.tsx` is the composite every input-driven game renders: `header` (the `SubHeader` and any status card), a content area (`data-game-content`: `min-h-0 flex-1 overflow-y-auto`, a CSS size container whose `--board-fit` lets the `board` utility size a board to the remaining height) and a dock (`data-game-dock`, `shrink-0`, hidden when empty). The root is `-mb-6 flex min-h-0 flex-1 flex-col`, so it fills `<main>` exactly and the page never scrolls; only the content area scrolls, and only when it truly doesn't fit. The dock is filled through the `dock` prop, or from anywhere inside the content with `<Dock>` (a portal into the dock element), which keeps state where it is (trivia's `Question`, the deck card views, Hangman's `Guessing`). On it: `BoardGameScreen` (turn header in the header; the reaction row, Resign and the finished card in the dock), the daily word (keyboard in the dock while playing; the grid is a `board` with aspect 5:6 capped by `--board-fit`), Hangman (keyboard + error line docked from `Guessing`), trivia rounds (the four answers docked from `Question`; the question, timer and reveal stay in the content), 20 Questions (Yes / Sort of / No, the ask form and the end-of-round buttons in the dock; the question log fills the content), the decks (Would You Rather and Never Have I Ever choices, the Truth-or-Dare Spin and the Flip / Next card row in the dock), Pictionary (the guess form in the dock; the drawer's tools stay with the canvas). Connect Four's drop row stays on the board.

**Pressable and feedback.** `components/ui/Pressable.tsx` (an `m.button`): pressed on pointerdown, released on pointerup / cancel / leave, a 90 ms spring to scale 0.94, `haptic("tap")` on press, an optional key-click (`click`, the `key` sound under the Sounds toggle), the `pressable` utility (`touch-action: manipulation`, no selection, no callout, no tap highlight); disabled gives nothing and the callers style used keys dimmer. Used by `LetterKeyboard`, trivia answers, deck choices and the 20 Questions answers. `lib/haptics.ts` names the patterns (`tap` 10, `success` [20, 40, 20], `error` [40, 30, 40]): the daily word buzzes success on a solve and error on an invalid word or a lost day, Hangman from the shared state (mask grew → success, misses grew → error, guesser only), trivia on the pick, Pictionary on a correct guess. `WordleGrid` pops a tile on entry (scale 1.1 → 1), fades colours over 150 ms (`transition-colors`) and flips a submitted row; Hangman's `WordTiles` pop revealed letters; `useReducedMotion` drops the scale and flip and keeps the colour change.

**Board games** (`/play/[gameId]`, `BoardGameScreen`, `boards/*`): engines in `lib/games/*` implement `Engine<S, M>` (`initialState`, `legalMoves`, `applyMove`, `status`, `mover`). Live state in RTDB `games/{id}` (JSON string, transactions) via `lib/db/games.ts`; the node's shape and the result wording are the pure `lib/games/node.ts` (shared with the server); results to `gameResults` and `pair.records`; `yourTurn`/`invite` pushes; `CloseGameMenu` (cancel invite / cancel 0-move game / resign); `FriendHereBadge`. Sizing (fix: board cell overlap): every board is the `board` utility (`width: 100%; max-width: max(200px, min(var(--board-max, 360px), 100dvh − 14rem))`, centred) plus `aspect-square`, with cells from `repeat(n, minmax(0, 1fr))` columns and rows (`min-h-0 min-w-0`, gaps in the grid), pieces in % of the cell or `cqw` of the grid (`@container` on the grid; `cqw` on the container element itself would resolve against the viewport), the Dots SVG through its `viewBox`; no `tap` on cells. `BattleshipGrid` (exported) and the placer share `GRID_TRACKS`; the two Battleship sections stack on phones and sit side by side from 700 px. Quick reactions (👏 😱 🤔 😂, both players while the game is active, in every phase): `GameReactions` (`ReactionRow`: one `onClick` per button, rendered under the board, or above it for Battleship whose two grids would push it below the fold; `ReactionBurst`: one floating element per push id, placed by `laneFor`, fixed to the viewport through a `Portal` so it shows wherever the screen is scrolled) over `hooks/useGameReactions`, which attaches exactly one `value` listener on `limitToLast(12)` of RTDB `gameReactions/{gameId}` per screen: the first snapshot is remembered and deleted, every key that appears in a later snapshot is admitted once (`lib/reactions.admitReaction`: keyed by push id, so the sender's optimistic event and the server echo are one reaction; ≤ 12 live, gone after 1.8 s). A cancel is handled once per attachment: `PERMISSION_DENIED` is final (the wrapper logged it once, nothing re-attaches), any other cancel re-attaches after 2 / 5 / 15 / 30 s; `lib/db/reactions.sendGameReaction` pushes `{ by, emoji, at }` and removes it after 5 s; a second tap within 350 ms is ignored. `inviteGame(type, me, friend, options?)` takes lobby options (`GameOptions`, today only the Dots board size) and `rematch` keeps them via `optionsOf`. `isMyMove(game, uid)` is the one "is it my move" check (tiles, Home card, header): it reads `turn`, except during Battleship placement where each player is on until their own fleet is in.
