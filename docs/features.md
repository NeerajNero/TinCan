## Chat (`/chat`) — `components/chat/ChatScreen.tsx`

- `hooks/useMessages.ts`: latest 50 live, `load older` pages of 50 (auto up to 3 pages by scroll, then a button; oldest pages dropped when back at bottom), optimistic sends, delivered/read marking.
- `MessageList` (day separators, unread divider, jump-to-latest FAB), `MessageBubble` (swipe-right reply, long-press menu, reactions), `MessageMenu` (react/reply/copy/edit ≤15 min/delete for me/everyone/schedule), `Composer` (text, attachments, hold-to-record voice with slide-to-cancel, GIF/sticker panel), `ScheduleSheet` (scheduled messages), `Ticks`.
- Media: `media/*` (AttachmentStrip, UploadBubble + ProgressRing, ImageViewer with pinch-zoom, VoicePlayer 1×/1.5×, MediaPanel for GIF/stickers). Upload pipeline in `hooks/useUploads.ts` → `lib/media/compress.ts` (≤1080 px, ~0.3 MB) / `lib/media/recorder.ts` (opus 32 kbps, ≤2 min) → `POST /api/media/sign` → Cloudinary (authenticated) → `POST /api/media/urls` → signed `variants` stored on the message. Rendering goes through `lib/mediaUrl.ts` (`variantUrl`) and `ui/CloudImage`. GIFs come from `GET /api/gif` (`lib/giphy.ts`).
- Typing: `hooks/useTyping.ts` (RTDB `typing/{uid}`, 1.5 s throttle, 3 s expiry). Unread badge: `hooks/useChatMeta.tsx`.
- Rendered URLs are filtered by `lib/safeUrl.ts`; links auto-linked by `lib/linkify.tsx`.
- **Backgrounds**: `ChatBackground` is one absolute layer behind the scroller (`backdrop` prop of `MessageList`); `ChatBackgroundPicker` (palette button in `ChatHeader`, and More → Chat wallpaper; "Shared with <friend>") writes `pair/main.chatBg` + `chatBgBy` (`lib/db/pair.setPairChatBg`) so both see the same wallpaper. `LiveEventsProvider` runs the one-time migration off the legacy `users/{me}.chatBg` (`lib/wallpaper.planWallpaperMigration`: copy to the pair when it has none, then `deleteField`) and toasts "<friend> changed the wallpaper 🎨" when `chatBg` changes with `chatBgBy` = the friend (no chat line, no push). Built-ins live in `content/chat-backgrounds.ts`; the photo option reads one bounded page of `memories`.
- **System lines**: every writer goes through `lib/chat/system.createSystemMessage(kind, text, meta?)` (server: `postSystemMessageAdmin(senderId, kind, text, meta?)`), sharing `systemMessageData` in `lib/chat/systemKinds.ts`: `{ type: "system", kind, text, meta?, senderId, status: "sent", createdAt }`. Kinds: sleep, wake, relationship, game-result, game-cancel, twenty-result, pet-adopt, pet-fed, pet-level, pet-hungry, garden-sticker, capsule-unlock, hangout (legacy: the removed hangout wheel wrote it; kept so old lines render), invite (rendered by `InvitePill`, see Invites under Play), recap (the monthly numbers line the tick posts on the 1st; `lib/recap.recapLine`). `SystemPill` shows the text, else a line derived from kind + meta, else ✨, so a row is never empty; old lines render unchanged. System lines never count as unread (badge, divider), never get read/delivered writes and never show ticks; the Home preview and toasts use the same `systemLine()`. The scroller is `relative` so the absolute background layer can't paint over in-flow rows (the phase 18 blank-gap bug).
- **Rendering cost**: `MessageBubble` is `React.memo` with stable callbacks; presence lives in `PresenceProvider` and typing in `useFriendTyping` inside the header, so the list never re-renders for them. `pnpm profile:chat` measures it.

## Play (`/play`) — `components/play/PlayScreen.tsx`

**Landing** (chore: play tab layout). `lib/play/catalog.ts` is the one list of everything Play opens (`PLAY_ENTRIES`: the seven board games, eight quick-play screens, eight together activities; id = how-to key, `short` label, `href`, `section`), with `playInfo()` for ids from storage, `playIdForPath` / `gameIdForPath` for routes and `pickSurprise`. Top to bottom: the "🎲 Surprise us" chip (random entry → the lobby flow for a board game, `router.push` otherwise, plus a toast naming it); "Jump back in" (invites for me, then active games ranked my turn → their turn → invite sent); "Recent" (`pair.play.recent`, first 4 known ids) and "Favourites" (`pair.play.favourites`), both hidden when empty; then Board games / Quick play / Together, each a `TileRow` of `CompactTile`s (3.5 visible, snap, the page gutter used for bleed) or, after "See all", the two-column `BigTile` grid. The per-section choice is `localStorage` `tincan:play-open:{section}` (`lib/play/usage.sectionOpen`: remembered value wins, else collapsed once Recent has entries). `badgeFor(entry)` gives every tile the same status (`TileBadge`: full text for big tiles, a short pill for compact ones): board games from the open-games list (Inviting… / Invite sent / Invited you! / Your turn / Their turn), the daily word from today's two wordle docs, Know-me from untaken quizzes, and "<friend> is here" from presence for any screen of its own. Long-press (touch) or right-click (mouse) on any tile opens a `Sheet` with Open and Pin to favourites / Unpin (`PlayTile.usePressMenu`: 450 ms, a 10 px move or a scroll cancels, the click that ends a long-press is swallowed). The dots size sheet, "Just finished" and the Record strip are unchanged.

**Usage** (`lib/play/usage.ts`, pure; `lib/db/play.ts` writes): `recordRecent(usage, id, by, now)` prepends `{ id, at: client ms, by }`, de-duplicates, caps at 8 and returns null when the same id was recorded less than 10 minutes ago (whoever opened it); `toggleFavourite` caps at 6 (null = full → "Favourites are full" toast). `components/play/PlayUsageTracker` (mounted once in `AuthGate`, no listener of its own) watches the pathname: a screen of its own resolves through `playIdForPath`, a board game (`/play/{id}`) through the open-games list from `LiveEventsProvider`, then `trackPlayOpen` writes `play.recent` (a per-device map stops two quick opens racing the snapshot into two writes). Both writes are dot-path `updateDoc`s on `pair/main`; the rules check the list sizes.

**Game catalogue** (`lib/games/catalog.ts`): names, emoji, routes and result wording for every game that writes `gameResults` (the seven board games, trivia, pictionary, the daily word), with `gameInfo()` falling back to a neutral entry for unknown types. Used by Recent games (`RecentGamesList`, inside an `ErrorBoundary`), the record strip (ten games, five per row), Home's game card, invites, result toasts and the system messages.

**Board games** (`/play/[gameId]`, `GameScreen`, `boards/*`): engines in `lib/games/*` implement `Engine<S, M>` (`initialState`, `legalMoves`, `applyMove`, `status`, `mover`). Live state in RTDB `games/{id}` (JSON string, transactions) via `lib/db/games.ts`; the node's shape and the result wording are the pure `lib/games/node.ts` (shared with the server); results to `gameResults` and `pair.records`; `yourTurn`/`invite` pushes; `CloseGameMenu` (cancel invite / cancel 0-move game / resign); `FriendHereBadge`. `inviteGame(type, me, friend, options?)` takes lobby options (`GameOptions`, today only the Dots board size) and `rematch` keeps them via `optionsOf`. `isMyMove(game, uid)` is the one "is it my move" check (tiles, Home card, header): it reads `turn`, except during Battleship placement where each player is on until their own fleet is in. Every board beyond tic-tac-toe / Connect Four / checkers is a `next/dynamic` chunk loaded only when that game is open.

- **Dots and Boxes** (`lib/games/dots.ts`, `boards/DotsBoard`): `dotsInitial(size)` for 5 or 6 dots per side (the Play tile opens a size `Sheet`; unknown sizes fall back to 5); edges as two strings, boxes as `A`/`B`; closing a box claims it and keeps the turn, so `turn` is stored; most boxes wins. The SVG board has a wide tap target around each gap, the owner's initial in each box and a glow on the last line.
- **Hangman** (`lib/games/hangman.ts`, `boards/HangmanBoard`): best of three, `hangmanSetterFor(round)` alternates from the inviter. The setter's `SetWord` form (letters and spaces ≤ 20, or a random `content/words-answers.json` entry) calls `setHangmanWord`: the word goes to `gamePrivate/{id}/{me}` = `{ word, round }` first, then a transaction moves the shared state to `guessing` with the mask (`startHangmanRound`) and pushes the guesser. Letters (on the shared `components/games/LetterKeyboard`: one 20-column `minmax(0, 1fr)` grid, used keys coloured and disabled, the in-flight key pulsing) call `guessHangmanLetter` → `POST /api/games/hangman/guess` (see api.md), which applies `applyHangmanGuess` with the private word and reveals `word` on the round when it ends; the previous round's card shows the word and its WordNet meaning (`fetchDefinition`, single words only). The setter's phone shows its own word in the tiles from its private subtree; the guesser sees the keyboard (green = in the word) and the six-part figure.
- **Battleship** (`lib/games/battleship.ts`, `boards/BattleshipBoard`): `FleetPlacer` keeps the fleet local (tap a cell for the selected ship's bow, Rotate, pointer-drag a placed ship, Random = `randomFleet`, Ready enabled when `fleetValid`), then `readyBattleship` writes `gamePrivate/{id}/{me}.fleet` (JSON) and `markReady` in a transaction (one ready → the other's move; both → `firing`, inviter first) with a your-turn push. Firing taps call `fireBattleshipShot` → `POST /api/games/battleship/shot`; the opponent grid shows my shots (✕ hit, • miss, darker when that ship is sunk via `sunk[opponent].cells`) and my grid my ships with their shots; a `last` of `sunk` that arrives after mount shows a banner and vibrates; "Waiting for X to place ships" carries an `InviteButton`. Fleets are never revealed, not even at the end.

**Deck games** (`/play/deck/[deck]`, `DeckScreen`): WYR, NHIE, truth/dare, conversation cards. Shared card in RTDB `cards/{deck}`; decks from `src/content/*.json` via `lib/decks.ts`; metadata in `lib/deckMeta.ts`.

**YouTube player rules** (watch and listen). `loadYouTubeApi()` in `lib/youtube.ts` loads `iframe_api` once per page, resolves at once when `YT.Player` exists, and wraps any existing `onYouTubeIframeAPIReady`. `YouTubePlayer` builds one player per mount, and only once its node is mounted, the API is loaded and a video id is known. Later ids are cued on the same player and unmounting destroys it. It passes `host: youtube-nocookie.com` and our `origin`. Local Play/Pause (`toggle` in `useSyncedPlayer`) calls the player inside the click handler, then writes RTDB. Remote state is applied only after this client joins: a one-time "Tap to join" overlay, a local Play/Pause, or loading the video yourself. Listen keeps the player at 200 px tall, the minimum YouTube allows, under an opaque cover, never hidden or 1 px. `onError` codes go to the Diagnostics log, and the player shows a friendly line. Codes 101 and 150 read "This video can't be embedded".

Heavy together screens are code-split through `together/lazy.tsx`.

## Pet (`/pet`) — `components/pet/PetScreen.tsx`

`AdoptCard` picks a species on first open; `content/pets` draws the sprite by species/level/mood as inline SVG built from named parts (`breath` › `body`, `eyes` › `eyeL`/`eyeR`, `mouth`, `cheeks`, `accessory`), each an `m.g` driven by its own animation controls. Hunger and happiness are derived from `pair.pet.hungerAt/happyAt` (`100 − minutes/14.4`, see `lib/pet.ts`); Feed/Play reset the timestamps and post system messages. Level = streak ÷ 7. Hunger push comes from the tick.

**Pet life (motion only).** `hooks/usePetLife.ts` owns everything animated for one mounted stage (`usePetLife` wires the app's writes, pair, toasts and pings into the injectable core `usePetMotion(opts, env)`, which the e2e harness drives with fakes); `components/pet/PetStage.tsx` renders it (HTML actor for whole-body moves around the part-animated SVG, the food prop, looping zzz, the sad 🌧️ cloud, particles) plus `PetDim` (card veil while asleep) and `LevelBadge`. `PetScreen` (180 px) and Home's `PetWidget` (88 px, `compact`: same motion, no particles) both use it. Pure helpers in `lib/petLife.ts` (unit-tested):
- Tap: one of 10 reactions (< 700 ms each), random with no immediate repeat (`pickReaction`). 3 taps within 2 s (`tapBurst`) → 3 s "excited" with a sparkle burst. Particles are capped at 20 alive (`capParticles`). Taps while asleep only make it stir.
- Long-press (400 ms): wiggle loop + a trickle of hearts; the Joy bar tops up at 20 points/s up to 100 (`heldHappiness`, one Play's worth) and is written **once on release** as `happyAt = sinceFor(value)` (`lib/pet.ts`, inverse of `statFrom`) via `db/pet.pettedPet`.
- Feed ≈ 2 s: cookie floats in, lean, three chomps with crumbs, the write lands after the chomps so the Food bar (`PetBits.StatBar`, scaleX tween) glides to full over 800 ms, then a satisfied wiggle + heart. Sleep ≈ 1.5 s (yawn, droop, settle → zzz, card dims) and wake ≈ 1.5 s (stretch, blink open, shake, sparkle, card brightens) write `sleepAt` **at the end**. Buttons are disabled while a sequence runs; a sequence cut short (another one, or leaving the page) still writes.
- Level-up: spin, confetti (full size), accessory pops on, badge counts up.
- Idle (paused while the tab is hidden): breathing, blink every 3–6 s, glances, a fidget every 15–30 s; hungry = tummy rumble + glance at Feed, sad = slow droop + cloud, happy = soft bob, asleep = slow breathing.
- The friend's actions: `db/pet` records each value this device writes; `petEvents(prev, next, consumeMyPetWrite)` turns the other changes into feed/play/sleep/wake, replayed here (stats held at their old values until the matching beat) with a toast such as "Sam fed Blob 🍪" (key `message`, so the "fed" system message toast collapses into it). A received hug ping → heart hop (on Home after the full-screen overlay).
- Chirps `petTap`/`petFeed`/`petSleep`/`petWake` in `lib/sounds.ts`, under the Sounds toggle.
- Reduced motion: `useReducedMotion()` + `<MotionConfig reducedMotion="user">`; no idle loops, reactions or particles, and actions write immediately.

## Cross-cutting

- **Auth & onboarding**: `components/auth/*` (SignInScreen, AuthGate, SetupScreen, TakenScreen), `components/onboarding/OnboardingScreen`, `components/pair/PairFullScreen`. `lib/auth.ts`, `lib/allowlist.ts`.
- **Shell**: `components/shell/AppShell`, `TabBar` (pending spinner on tapped tab), `OfflineBanner`; `lib/tabs.ts`.
- **Toasts**: `components/toast/ToastProvider` (optional `actions` buttons, used by invites). **Live events**: `components/live/LiveEventsProvider` (pings, lamp, messages, daily answer, open games, garden, invites). **Push**: `components/push/PushController`, `lib/push.ts` (token), `lib/notify.ts` (client → `/api/push`).
- **Reported Firebase access**: `lib/firebase/fs.ts` (Firestore, metered) and `lib/firebase/rt.ts` (RTDB) are the only places that import the SDKs (ESLint `no-restricted-imports`). Every rejected write and every denied read or listener is logged to `lib/diagLog` as `[write] op path → code` / `[read] …` (More → Diagnostics), and `components/dev/WriteFailureToasts` (development only, mounted by `AuthGate`) toasts permission-denied so a missing rule shows up on the first tap.
- **UI kit**: `components/ui/*` (Avatar, Button, Card, CloudImage, Input, Portal, Sheet, Skeleton, Spinner, Splash, Switch, TabError). `CloudImage` is the only way to render a Cloudinary photo (srcset, blur-up, lazy); `next/image` is not used anywhere.
- **Web vitals**: `providers/WebVitals` logs CLS/LCP/INP to the console in development only.
- **Service worker**: `src/app/sw.ts` (precache, `/offline` fallback, runtime caches for Cloudinary/OSM/GIPHY/ytimg images, NetworkOnly for Firebase/Google/`/api`, FCM background handler, same-origin notification click, the share-target POST stash).
- **Share into Tincan** (`/share`, `components/share/ShareScreen`; pure parts in `lib/share.ts`, Cache API access in `lib/shareStash.ts`): the manifest's `share_target` (`src/app/manifest.ts`: POST, multipart, `title`/`text`/`url`/`files` images only) lands on the worker, which stores the fields as JSON at `/share-stash/{nonce}` and each image at `/share-stash/{nonce}/file/{i}` in the `tincan-share` cache and 303-redirects to `/share?id={nonce}`. The page reads the stash (dropped after 30 min), `classifyShare` picks youtube / link / text / images (a link in `text` counts, as Android often sends it there), and the destinations call the existing helpers: `loadVideo` (Play in Watch / Listen), `savePlaylistItem` (Save to Watch / Listen playlist), `sendText` + `notify("message")` (Send to chat, with the message editable for links and text), `compressImage` + `uploadToCloudinary` + `sendMedia` + `notify` per image (caption on the first) or `uploadImages` + `addMemories` (Save to Memories). Every action clears the stash and goes to that screen. Without a stash the page explains how to share. Signed out, `AuthGate` sends `/share…` to `/signin?next=…` and `SignInScreen` returns there (`sameOriginPath`: same-origin paths only).
- **Home-screen shortcuts** (`manifest.shortcuts`): Chat, Ping (`/?ping=1` → `HomeScreen` passes `highlight` to `PingRow`, which scrolls the row in, glows it for 2.6 s and replaces the URL with `/`), Daily word, Pet; icons `public/icons/shortcut-*-96.png` from `pnpm icons` (vector glyphs on the tab colour, maskable).
